## 已定产品决策（不可更改）

- 扫码入口在 **AddItem 表单页顶部**（"扫码快填"按钮）
- 扫码 → 按条形码查历史记录 → **搜索建议列表**（名称 + 最近入库时间，按最近排序）→ 点选其一 → **预填表单**（名称/分类/单位/保质期天数带入，生产日期和数量留给用户）→ 用户确认后手动入库
- 历史无该条码 → 进空表单，**该条码随本条物资记录保存**
- 同一码可能对应多条历史 → 列表保留选择权，不自动填充
- 一件实物一条记录，不做批次归组

## 实现要求

1. **扫码能力**：用 ScanKit（`@kit.ScanKit` 的 `scanBarcode.startScanForResult` 或自定义扫码页，优先系统默认扫码 UI；若自定义 UI 则需 CAMERA 权限——优先免权限方案）。API 24 基线。
2. **数据模型**：`Material` 增加可选字段 `barcode?: string`（数据库表加 `barcode TEXT` 列；若已有迁移机制则走迁移，否则在 `MaterialDb.init` 中做 `ALTER TABLE ... ADD COLUMN` 的兼容处理——检查现有表是否已有该列再决定）。
3. **查询**：`MaterialDb` 增加 `findByBarcode(barcode: string): Promise<Material[]>`（按 `updatedAt` 或 `createdAt` 倒序）。
4. **搜索建议 UI**：扫码成功且历史有匹配 → 弹出半模态/列表（名称 + 数量单位 + 最近入库时间），点选即预填；底部留"都不对，手动填写"选项（丢弃预填、仅记录条码）。
5. **AddItem 改造**：顶部加"扫码快填"按钮；接收扫码结果并预填相应字段；保存时把 barcode 写入记录（手动入库时若有扫码结果也一并保存）。
6. **中文 UI**，沿用现有视觉风格（品牌色 #2E9E6B、圆角卡片、#F5F6F8 背景）。
7. 端侧、离线；不引入任何网络请求。

## 验收标准

- 真机/模拟器可扫一维码（EAN-13）→ 有历史时出建议列表 → 点选后表单正确预填（生产日期不预填，留给用户）→ 保存后记录带 barcode
- 同一条码第二次入库：建议列表能查到上一次记录
- 陌生条码：直接进空表单，保存后条码入库
- 无模拟器依赖项可用模拟器验证 UI 流程；扫码交互若模拟器不支持，代码需做能力判断并给提示
